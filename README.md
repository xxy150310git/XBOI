# XBOI 团队分数站

洛谷团队 XBOI 的分数与 X 币查询站点。前端是纯静态多页面（零构建），后端用 Supabase。

```
XBOI/
├─ index.html              首页
├─ leaderboard.html        排行榜
├─ query.html              X 币查询
├─ redeem.html             道具兑换（领兑换码）
├─ quiz.html               答题赛（选择 / 判断 / 填空）
├─ admin.html              管理后台（仅管理员可见）
├─ supabase-schema.sql     数据库建表脚本（在 Supabase 控制台执行一次）
├─ README.md               本文件
└─ assets/
   ├─ css/style.css        主题样式（默认天依蓝青，可换色）
   ├─ vendor/supabase.js   Supabase 客户端库（本地一份，不依赖外网 CDN）
   └─ js/
      ├─ theme.js          ← 放在 <head>，负责换主题色与背景图
      ├─ config.js         ← 只有这个文件需要你改
      ├─ rules.js          附录 2 奖励算法
      ├─ items.js          附录 1 道具表（图标与演示数据）
      ├─ quiz.js           答题的题型定义、判分规则与演示题库
      ├─ mock.js           演示数据（未配置后端时使用）
      ├─ ui.js             公共界面工具
      ├─ db.js             数据访问层
      ├─ auth.js           登录按钮、登录弹窗、改密码
      ├─ page-index.js
      ├─ page-leaderboard.js
      ├─ page-query.js
      ├─ page-redeem.js
      ├─ page-quiz.js
      └─ page-admin.js
```

> 没有配置 Supabase 时整站自动进入演示数据模式，可以直接打开看效果；填好配置后自动切换到真实数据。
> 演示模式下用 `Tianyi` 或 `xxy150310` 登录，密码统一是 `123456`。

## 第一步：建 Supabase 项目

1. 打开 <https://supabase.com>，注册并新建一个项目（区域选离你近的，例如新加坡）。
2. 等数据库初始化完成，进入左侧 **SQL Editor → New query**。
3. 把 `supabase-schema.sql` 的内容整段粘贴进去，点 **Run**。
   执行成功后会生成 9 张表、3 个视图，以及登录、兑换、答题、管理端的一整套函数和权限策略。

> **已经建过库的，把脚本再整段跑一次就行。**脚本里所有对象都写成可重复执行的形式，
> 不会动你已有的数据，只是把新增的表和功能补上。

## 第二步：登录方式与管理员

**不需要在 Supabase 里建账号**。成员直接用「洛谷用户名 + 密码」登录：

- 每名成员的初始密码统一是 `123456`，登录后点右上角的名字就能改掉。
- 顶栏上登录按钮的旁边还有一颗独立的「退出」按钮，点一下就直接退出登录，不用先进账号面板。
- 新成员入队时，数据库会自动给他配一份初始密码（触发器 `trg_members_default_password`）。
- 谁是管理员，看 `members` 表里的 `role` 字段。把它改成 `admin`，那个人重新登录后就能看到「管理后台」。
- 密码只以 bcrypt 哈希存在 `member_credentials` 表里，这张表**不对外开放任何读权限**，
  登录、改密码、兑换、答题判分全部走服务端函数。

> 第一次建库时，先把队长的 `role` 改成 `admin`，其他人保持 `member`：
>
> ```sql
> update public.members set role = 'admin' where luogu_name = '你的洛谷用户名';
> ```
>
> 初始密码很弱，建议让大家都改一遍。改密码在页面右上角头像里，不用管理员帮忙。

## 第三步：填配置

左侧 **Project Settings → API**，复制两个值，填进 `assets/js/config.js`：

```js
SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJhbGciOi...',
```

`anon key` 是设计上就公开给浏览器的密钥，安全性由数据库里的行级安全策略保证，可以放心写在页面里。**不要**把 `service_role key` 填进来。

## 第四步：本地预览

在项目目录下起一个静态服务器（随便一种）：

```bash
python -m http.server 8765
# 然后浏览器打开 http://127.0.0.1:8765/
```

## 第五步：部署

整站没有任何构建步骤，把这几个文件和 `assets/` 目录原样上传到任意静态托管即可：

- **GitHub Pages**：把文件推到仓库，Settings → Pages → 选分支根目录。
- **Vercel / Cloudflare Pages / Netlify**：直接拖拽目录，框架预设选「其他 / 静态」。
- **对象存储 + CDN**：上传后把默认首页设为 `index.html`。

如果托管在自定义域名上，记得回 Supabase 的 **Authentication → URL Configuration** 把站点地址加到允许列表。

## 答题赛怎么用

**管理员**：进「管理后台 → 答题赛」

1. 先建一场赛：填名称、**开赛时间**、**作答时长（分钟）**、**积分倍率**，决定要不要发布。
   时间窗 = 开赛时间 ~ 开赛时间 + 作答时长，到点自动结束。
2. 出题。两种方式随便挑：

   **一题一题加**：在「题目」里选题型，每题都能单独设分值：

   - **选择题**：选项每行一个（依次对应 A、B、C…），答案填字母，例如 `A`。
   - **判断题**：答案填 `T`（对）或 `F`（错），写「对」「错」「√」「×」也能识别。
   - **填空题**：可以写多个可接受的答案，用 `|` 隔开，例如 `main|Main`；判分忽略大小写和首尾空格。

   **批量导入**：题目多的时候，把题目写成一个 `.js` 文件，用「批量导入题目」一次导进去，
   格式见下面「题目文件怎么写」。

3. 「本场成绩」里能看到谁交卷了、卷面多少分、最终拿了多少积分。

**成员**：进「答题赛」，只有进行中的那场能点「开始作答」。页面上有倒计时，时间到自动交卷；
一张卷只能交一次，交完立刻结算并显示逐题复盘。

**积分怎么算**：`最终积分 = 卷面得分 × 积分倍率`（四舍五入到整数）。
这份积分有两个去处：一是直接作为 X 币发到账户（流水分类是「答题奖励」），
二是累计进排行榜的「答题积分」列。

> 答案不会下发给浏览器：题目表 `quiz_questions` 不给任何读权限，
> 成员拿到的是去掉答案的题面，判分在服务端函数 `quiz_submit` 里做。

## 题目文件怎么写

题目多的时候不用一题一题敲。在「管理后台 → 答题赛 → 批量导入题目」里：

1. 确认上面「题目」那一栏已经选中了要导入的那场答题赛。
2. 点「下载模板」拿到一份 `XBOI-题目模板.js`，照着改成自己的题。
3. 选文件 → 看预览（会统计题量、满分，并把有问题的地方指出来）→ 点「确认导入」。
4. 想用文件里的题**覆盖**原来那场，勾上「导入前先清空这一场已有的题目」。

模板长这样：

```js
XBOI_QUESTIONS = [
  {
    type: 'choice',            // 题型：choice 选择 / judge 判断 / fill 填空
    stem: '下面哪个是 C++ 里输出到屏幕的语句？',
    options: ['cin >> a;', 'cout << a;', 'printf("%d", a);', 'scanf("%d", &a);'],
    answer: 'B',               // 填选项字母、序号（从 1 数）或选项原文都行
    score: 10,                 // 不写就用导入面板上的「默认分值」
    sort: 1                    // 排序，小的排前面；不写就按文件里的先后
  },
  { type: 'judge', stem: '在 C++ 中，数组下标从 0 开始。', answer: 'T', score: 10 },
  { type: 'fill',  stem: 'C++ 程序的入口函数叫 ______。', answer: 'main|Main', score: 15 }
];
```

**文件几种写法都认**：整个文件直接是一个数组、`XBOI_QUESTIONS = [ … ]`、
`QUESTIONS = [ … ]`、`module.exports = [ … ]`、`export default [ … ]`。

**题型可以省略不写**，会自动猜：有 `options` 的当选择题，答案是 `T`／`F`／`对`／`错`
之类的当判断题，其余当填空题。中文题型名（`选择题`／`判断题`／`填空题`）和拼音缩写（`xz`／`pd`／`tk`）也认。

**答案的写法**：

| 题型 | 可以怎么写 |
| --- | --- |
| 选择题 | 选项字母 `B`（大小写都行）、从 1 数起的序号 `2`，或者直接把选项原文粘过来 |
| 判断题 | `T`／`F`、`对`／`错`、`正确`／`错误`、`√`／`×`、`true`／`false`、`1`／`0` |
| 填空题 | 多个可接受的写法用 `|` 隔开，例如 `main|Main`；判分忽略大小写和首尾空格 |

> **只要有一道题不对，整份就不导入**，预览里会指出是第几题、错在哪，改完再选一次即可 ——
> 这样不会出现「导进去一半」的尴尬局面。

> 一次最多导入 **500 道**题，超过的话把文件拆成几份分次导。

> 文件的编码不用管，UTF-8 和 GBK（DevC++、记事本在中文 Windows 上的默认编码）都能正常读出来。

> 导入时浏览器会把这个文件**执行一次**来取数据，所以只导你自己写的（或信得过的）文件。

## 主题设置

点右上角的调色盘图标，可以：

- **换主题色**：8 个预设色板，或者自己取色。整站配色（按钮、导航、阴影、底纹、表格表头）会跟着色相一起变。
- **换背景图片**：选一张本地图片，会自动压缩后存在你自己的浏览器里（约 1600px 长边、JPEG 质量 0.82），
  上面压了一层白色薄纱保证文字看得清。可以随时「恢复默认」。

> 主题是**按人存在浏览器 localStorage 里的**，不会影响别人看到的配色，换设备要重新设。
> 因为存放在本地，用无痕模式或者清了浏览器数据就会回到默认主题。

## 常见问题

**Q：页面底部一直显示「演示数据模式」？**
`assets/js/config.js` 里的两项还是占位值。注意 `SUPABASE_URL` 必须以 `https://` 开头，`SUPABASE_ANON_KEY` 要粘完整。

**Q：登录提示「洛谷用户名或密码不对」？**
用户名要写洛谷用户名（不是昵称）。第一次登录用 `123456`；如果改过密码就用新密码。

**Q：登录后看不到「管理后台」？**
说明当前账号的 `role` 还是 `member`。让已有的管理员在后台「成员管理」里把你的身份改成「管理员」，
或者直接在 SQL Editor 里执行 `update public.members set role = 'admin' where luogu_name = '你的用户名';`。

**Q：后台保存时报 `只有管理员可以做这个操作`？**
登录过期或者当前账号不是管理员。点右上角头像退出后重新登录试试。

**Q：`relation "v_leaderboard" does not exist`？**
建表脚本没有跑完整。回到 SQL Editor 把 `supabase-schema.sql` 重新整段执行一次（脚本可以重复执行）。

**Q：兑换 / 答题页提示「数据表还没建好」？**
这是新增功能的表还没建。把最新的 `supabase-schema.sql` 再整段执行一次即可。

**Q：兑换时报「X 币不足」？**
兑换会立刻扣币，余额按流水实时累加。先让对方在「X 币查询」里确认余额，或者由管理员在后台手工调整。

**Q：兑换码发出去后怎么算用掉了？**
兑换码只是凭证，不自动生效。管理员在后台「道具兑换」标签页找到那张码，核对无误后点「标记已使用」。
标记后状态变成已使用、记下核销时间，页面上就不会再出现「标记已使用」按钮。

**Q：兑换码会过期吗？**
会，按附录 1 是 90 天。过期后状态自动显示为「已过期」，核销按钮消失。已经扣掉的 X 币不会退回。

**Q：答题赛时间还没到 / 已经结束，进不去？**
这是设计如此。只有开赛时间到、且没超过作答时长时才能打开卷子，交卷也必须在时间窗内（到点会自动交）。

**Q：答题后积分没到账？**
只有拿到分（`最终积分 ≠ 0`）才会记一条 X 币流水。交卷后可以在「X 币查询」里看到分类为「答题奖励」的记录。

**Q：导入题目时提示「这个 JS 文件没能执行成功」？**
文件里有语法错误（多半是少了个逗号或者引号没配对）。按提示里的报错行号回去改一下再选一次。
另外导入是按整份来的，题目数组旁边的括号写错也会走到这条提示。

**Q：导入题目时提示「先在上面「题目」那一栏选一场答题赛」？**
导入是往「当前选中的那场」里放的。先在「题目」卡片里选好目标答题赛，再回来选文件。

**Q：导入后题干里的中文变成乱码了？**
正常不会。文件会先按 UTF-8 读，读不出来就自动按 GBK 再读一次，两种编码都支持。
如果还是乱码，多半是编辑器用了别的编码（比如 UTF-16），换 UTF-8 或 GBK 另存一次即可。

**Q：同一份文件重复导入会怎样？**
会重复追加一份（题目没有去重逻辑）。想覆盖原来那场的题目，导入前勾上「先清空这一场已有的题目」。

**Q：排行榜和查询页显示的是旧数据？**
视图是实时计算的，不需要手动刷新；如果是浏览器缓存，强刷一次（Ctrl + F5）。

**Q：想让某个成员退出但保留记录？**
在后台把该成员的「在队状态」改成「已退队」，不要直接删除。删除会连同他的全部流水、成绩、作答记录一起清掉。

**Q：数据库连不上但想先给队友看页面？**
什么都不用改，保持演示模式即可，页面上的数据是内置示例。
